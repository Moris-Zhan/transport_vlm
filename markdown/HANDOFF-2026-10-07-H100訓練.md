## 3. Conda 環境

| env | 內容 | 用途 / 備註 |
|---|---|---|
| `Mistral3` | Python 3.10 + torch 2.13.0+cu126 + 訓練套件（transformers 5.16.1 / trl 1.12.0 / peft 0.20.0 …），**無** flash_attn / vllm / openai / xformers | 最乾淨的基底，可當退路 |

| `Mistral3-fa-vllm` | `Mistral3-fa` clone + vllm 0.28.0+cu129（torchaudio/torchcodec 換成 cu126 build；protobuf 降為 6.33.6） | **目前建議使用：訓練與推論共用** |

- 三層 env 是逐層 clone，上一層都沒有被修改（以 `pip freeze` 前後比對確認過）。
- 原本的 `Mistral` env（torch 2.13.0+cu130，GPU 不可用）**目前已不存在**於 `/root/miniconda3/envs/`
  （非本次工作刪除）。
- 重建方式：
  - 腳本分層：`scripts/setup_flash_attn_env.sh`（Mistral3 → Mistral3-fa）、`scripts/setup_vllm_env.sh`
    （Mistral3-fa → Mistral3-fa-vllm），兩支都含驗證，已對既有 env 實跑通過。
  - 一次到位：`requirements-Mistral3-fa-vllm.txt`（檔頭有完整步驟：建 env → `pip install -r` →
    下載 CUDA 12.6 redist → 編譯 flash-attn → 驗證）。已在全新 env 做過 `pip install --dry-run`，
    216 個套件解析成功且版本與現有環境一致；**尚未實際從零完整安裝驗證**。

### 為什麼這樣裝（踩過的坑）

1. **flash-attn 沒有現成 wheel**：官方 release 只到 torch 2.8、HF kernel hub 只到 torch 2.9。
   torch 2.8 的 wheel 裝在 torch 2.13 上 import 會 `undefined symbol`（ABI 不合）→ 必須自己編譯。
2. **conda 的 cuda-nvcc 不能用**：會強制裝 conda gcc，且與 env 既有的 `ld_impl` 衝突 →
   改用 NVIDIA 官方 redistributable tarball 解壓到 env 底下的 `cuda-12.6/` 當 `CUDA_HOME`。
3. **vllm 不能直接 `pip install vllm`**：PyPI 版是 CUDA 13 build → 改用 GitHub release 的
   `vllm-0.28.0+cu129` wheel（vllm 0.27~0.31 都釘 torch==2.13.0，不會換掉 torch）。
4. **裝 vllm 會帶進 CUDA 13 版 torchaudio/torchcodec**：transformers 載入時 import torchaudio，
   導致 `vllm serve` 啟動即 `libcudart.so.13: cannot open shared object file` →
   換成同版本 `+cu126` build（`--no-deps`）。

## 4. 程式碼變更

### `scripts/fine_tuning_vlm_trl_traffic_tune_ministral_simplified.py`（正式訓練腳本，`run_formal_finetune.sh` 的預設）

- **訓練參數對齊 `v2.py`**（透過 `parser.set_defaults()` 只覆寫這支腳本的預設值，不影響共用 config 與
  fastmerge.py；CLI 明確傳值仍優先）：
  - `warmup_ratio` 0.03 → **0.08**、`max_grad_norm` 0.3 → **0.5**
  - `resource_mode` auto → **manual**，固定 **batch 8 × accumulation 2**
  - `early_stopping_patience` 15 → **0**（關閉，跑滿 epoch；eval 仍會跑，只用於觀察）
  - LoRA 加上 **`modules_to_save=["lm_head", "embed_tokens"]`**
  - `attn_implementation` 預設 **`flash_attention_2`**（沒有 flash_attn 的 env 需加 `--attn_implementation sdpa`；
    啟動時會先檢查 flash_attn 能否 import）
- **支援 Mistral-Small-3.2-24B**（同時保留 Ministral-3-8B 支援）：
  - 只有底模型 config 帶 `quantization_config`（Ministral FP8）時才套 `FineGrainedFP8Config(dequantize=True)`
  - Mistral-Small 本地目錄沒有 processor 檔案 → 自動改從 HF hub
    `mistralai/Mistral-Small-3.1-24B-Instruct-2503` 載入 processor（**需要網路或 HF cache**），
    並用底模型 config 覆寫 `patch_size`/`spatial_merge_size`
  - 合併階段複製 tokenizer 檔案時略過不存在的檔案
- `CUDA_VISIBLE_DEVICES` 改成 `setdefault("0")`：**Mistral-Small 必須外部設 `CUDA_VISIBLE_DEVICES=0,1`**，
  單卡會在第一個 step OOM
- SFTConfig 加 `loss_type="nll"`：TRL 1.12 預設的 `chunked_nll` 在模型切到多卡時會
  `AttributeError: 'functools.partial' object has no attribute '__func__'`，且與 `modules_to_save` 的
  lm_head 有相容風險

### `utils/fine_tuning/config.py`

- `TrainingConfig` 新增 `attn_implementation`（共用預設 `"sdpa"`）與對應 CLI `--attn_implementation`
  （choices：sdpa / eager / flash_attention_2）。純新增，不改既有腳本行為。

### `scripts/monitor_progress.sh`（手動監控訓練）

- 修正 `LOG_FILE` 被註解掉、`set -u` 下找不到訓練程序時直接崩潰

- 修正 `--new_run` 時算出不存在的 run{N+1}（改用「資料夾修改時間 vs 程序啟動時間」判斷）
- 進度條只挑訓練進度條（排除 `Loading weights:`、eval 進度條；以 max_steps 比對）
- `sft_config.yaml` 路徑改為 `<run>/configs/`
- 新增「最新 loss」區塊（train / eval）
- 用法：`./scripts/monitor_progress.sh`（快照）或 `-w`（每 10 秒刷新）

## 6. 待決策 / 未解決事項（開始正式訓練前請先處理）

1. **GPU0 記憶體幾乎滿**（flash 版峰值 80.9/81.5GB，GPU1 只用 45GB），長時間訓練有 OOM 風險。建議選項：
   - (a) 在 `max_memory` 調低 GPU0 上限，讓更多層放到 GPU1（建議，需小改腳本）
   - (b) batch 改 4 × accumulation 4（effective batch 不變）
   - (c) 維持現狀，靠 `run_formal_finetune.sh` 的自動重試從 checkpoint 接續
2. **GPU0 的外部程序**可能再出現，正式訓練前需確認 GPU0 沒有其他人在用。
3. **訓練長度與磁碟**：5 epoch ≈ 30000/16 × 5 ≈ 9375 step，以 19 s/step 估約 **50 小時**；
   每份 checkpoint 約 8.7GB（`save_total_limit=2` 約佔 17GB）。可考慮先限制 `--max_steps` 或重新開啟 early stopping。
4. **啟動方式**：建議用 `run_formal_finetune.sh`（自動重試），但其 `FINETUNE_PYTHON` 預設仍指向不存在的
   `fine_tune_vlm` env，需帶入：
   ```bash
   FINETUNE_PYTHON=/root/miniconda3/envs/Mistral3-fa-vllm/bin/python CUDA_VISIBLE_DEVICES=0,1 \
     ./scripts/run_formal_finetune.sh --model_id Mistral-Small-3.2-24B-Instruct-2506 --new_run
   ```

   （`smoke_test_train_merge_vllm.sh` 同樣問題；是否改預設值尚未決定）
5. **未驗證的流程**：

   - eval（`eval_loss`）尚未看到完整跑完
